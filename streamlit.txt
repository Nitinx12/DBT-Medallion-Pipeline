--------------------------------------------------------------------------------
0. BIG PICTURE
--------------------------------------------------------------------------------
- Interactive Streamlit + Plotly dashboard that reads DIRECTLY from the
  `gold` star schema in Postgres (no extracts, no CSVs, no middle layer).
- Multipage app. Entry point is dashboard/home.py; the sidebar pages are
  dashboard/pages/1_Sales.py .. 4_Categories.py (numeric prefixes control
  sidebar order).
- Run it (always via `streamlit run`, NEVER bare `python ...home.py` —
  bare python has no Streamlit runtime and every widget call degrades
  into "missing ScriptRunContext" warnings):
      uv run streamlit run dashboard/home.py
      # -> http://localhost:8501
- Deployed demo (Streamlit Community Cloud) reads credentials from
  `st.secrets` instead of `.env`; local runs use `.env` via
  src/utils/engine.py + src/utils/connection.py, so nothing extra to
  configure.
- Every page follows the same pipeline: page config -> inject CSS ->
  sidebar_filters() -> parameterized SQL from the query layer ->
  Plotly chart (styled by shared style()) or dataframe + CSV download.
- Aggregation ALWAYS happens in Postgres (GROUP BY in SQL); only
  summarized rows travel to the app. The single exception is the bounded
  200-row recent-orders sample, which is filtered client-side for search.
- Soft-delete convention: every query filters `foi.is_active = true`
  AND `o.is_active = true`, matching the gold layer convention.

2. PAGES — dashboard/pages/
--------------------------------------------------------------------------------
All four pages share the same skeleton: docstring, PROJECT_ROOT bootstrap,
`import streamlit as st`, set_page_config, inject_css(), title,
`sidebar_filters(key_prefix="<page>_")`, query calls, charts/tables.
The per-page `key_prefix` ("sales_", "prod_", "cust_", "cat_", "home_")
namespaces sidebar widget + session-state keys so each page keeps
independent filter state.

--- 2a. pages/1_Sales.py (56 lines): "Sales page — revenue trend and store mix."
- Granularity radio: Day / Week / Month (default Week), lowercased before
  passing to get_revenue_trend (which only accepts "day"|"week"|"month").
- Queries: get_revenue_trend(filters, granularity),
  get_revenue_by(filters, "store"), get_revenue_by(filters, "payment_method").
- Layout: full-width area chart (revenue_trend_chart), then two columns:
  left "Revenue by Store" bar chart + CSV download
  (revenue_by_store.csv, key dl_sales_store); right "Revenue by Payment"
  donut. Each block renders only `if not <df>.empty`.
- All plotly charts pass `config={"displayModeBar": False}` (hides the
  Plotly modebar for a cleaner look).

--- 2b. pages/2_Products.py (66 lines): "Products page — top products, brands, category treemap."
- Queries: get_top_products(filters, limit=10),
  get_revenue_by(filters, "brand", limit=10),
  get_category_brand_treemap(filters).
- Layout: "Top 10 Products" table + CSV (top_products.csv, key
  dl_prod_top); then two columns: left horizontal Top-10-Brands bar
  (built inline with px.bar on x=revenue/y=brand, y-axis
  categoryorder="total ascending", WALMART_BLUE markers, height 420);
  right Category -> Brand treemap (px.treemap path
  ["category_name","brand_name"], values=revenue, currency=False,
  legend=False, height 420).
- This page imports plotly.express + WALMART_BLUE + style directly
  because its brand bar is bespoke; everything else uses lib/charts.py.

--- 2c. pages/3_Customers.py (41 lines): "Customers page — top customers and recent orders."
- Queries: get_top_customers(filters, limit=10),
  get_recent_order_lines(filters, limit=200).
- "Top 10 Customers" table + CSV (top_customers.csv, key dl_cust_top).
- "Recent order lines (200)": a `st.text_input` search box; when a query
  is typed, EVERY column is cast to str, lowercased, and substring-matched

  the bounded 200-row sample. Result table + CSV (recent_orders.csv,

3. HELPERS — dashboard/helpers/
--------------------------------------------------------------------------------
--- 3a. helpers/theme.py (449 lines): the design system. Single source of
truth so charts, tables, and cards share one professional look.
- Brand tokens: WALMART_BLUE "#0071CE", WALMART_YELLOW "#FFC220".
- PALETTE (ordered, 9 entries): Walmart blue, yellow, deep blue #004C91,
  sky #00A9E0, teal/success #0E9F6E, coral/alert #E7462A, violet #7B5CFF,
  slate #6E7B8B, muted slate #94A3B8 (for "other" slices). Used as the
  Plotly colorway and donut sequence.
- SEMANTIC dict: success/danger/warning/neutral, border/border_strong
  (translucent slate), surface/surface_alt/surface_muted backgrounds,
  text/text_muted/text_faint.
- Fonts: FONT_FAMILY Inter stack, FONT_MONO JetBrains Mono stack.
- SCALE_BLUE / SCALE_BLUE_YELLOW sequential scales for continuous charts.
- style(fig, currency=True, legend=True, height=380, show_grid_y=True):
  transparent plot+paper background (cards supply the surface), shared
  font/colorway/margins/hoverlabel (dark tooltip), horizontal legend on
  top, bargap 0.22, hidden X grid + subtle Y grid, currency Y axis
  ($ prefix, ",.0f" ticks, ",.2f" hover), bar marker line width 0.
- inject_css(): one <style> block covering — Inter/JetBrains Mono font
  import; #F8FAFC app background; blurred sticky header; hidden footer
  element; global font family; sidebar surface + uppercase section heads;
  .dash-card surface/hover/accent variants; the full .kpi-card system
  (4-col grid -> 2-col under 1100px -> 1-col under 600px, top accent bar
  via --kpi-accent, label/value/delta-pill/foot classes with
  up-green/down-red/flat-grey variants); section heads; filter chips;
  hr polish; tab styling; stMetric card fallback (so native metrics also
  look like cards); dataframe/expander/button/alert polish; scrollbars;
  Plotly modebar fade; empty-state; .dash-footer.

--- 3b. helpers/components.py (232 lines): reusable UI blocks. Pages stay
focused on layout/data flow; ALL raw-HTML card rendering lives here.
- _safe_html(raw): dedents, strips every line, drops blank lines, joins
  into ONE line. WHY IT EXISTS: Markdown treats 4+-space-indented lines
  as code blocks and blank lines end an HTML block — both failure modes
  render styled cards as literal `<div...>` text with a copy button
  (this exact bug hit the KPI cards). Every st.markdown HTML call in this
  file is routed through _safe_html; NEVER pass indented triple-quoted
  HTML to st.markdown directly.
- _DELTA_ICON = {"up": "▲", "down": "▼", "flat": "—"}; _delta_state(pct):
  None -> flat; pct > +0.05 -> up; pct < -0.05 -> down; else flat
  (deadband avoids flickering on noise).
- kpi_cards(revenue, orders, customers, aov, deltas, delta_label="vs
  prior"): builds ONE 4-card grid in a single st.markdown call. The four
  cards: Total Revenue (icon money-bag, value $X rounded, foot "Gross
  merchandise value", WALMART_BLUE accent) / Orders (package icon, int
  with thousands separators, foot "Distinct order_id", #0E9F6E) /
  Customers (people icon, foot "Unique shoppers", #7B5CFF) / Avg Order
  Value (receipt icon, $X.XX, foot "Revenue / orders", WALMART_YELLOW).
  Delta pill: "— no prior period" (flat class) when pct is None, else
  "{icon} {pct:+.1f}% {delta_label}" with up/down/flat class. All dynamic
  text is html-escaped. Used ONLY by home.py.
- card_header(title, subtitle, accent="blue"|"amber"|"teal"): card title +
  optional subtitle + 28px accent bar (standalone block above a chart).
  Currently reserved (no page calls it yet).
- section_head(title, subtitle): spaced h3 + muted paragraph row.
  Currently reserved.
- filter_chips(filters): compact chip row — date range chip (exclusive
  end noted), store count (amber), category count (slate), status count
  (slate). Currently reserved.
- empty_state(title, hint): dashed-border centered notice. Used by
  dataframe_with_download on empty frames.
- dataframe_with_download(df, filename, key, column_config=None): empty
  guard -> empty_state; else st.dataframe (full width, hidden index) +
  CSV download button (utf-8, mime text/csv). Used by ALL four pages with
  per-table filenames/keys (see §2).
- footer(): .dash-footer bar — "© 2026 Walmart Medallion Pipeline · gold
  schema · live from Postgres" + source link + "Built with Streamlit +
  Plotly". Used by home.py.

--- 3c. helpers/queries.py (305 lines): ALL SQL against gold lives here.
Two rules drive the file: (1) every value is bound via SQLAlchemy text()
+ params — NEVER f-string-interpolated — so sidebar input can't inject
SQL; (2) filtering AND aggregation run in Postgres, only summarized rows
return.
- GOLD = config.POSTGRES_SCHEMA_GOLD (schema name from .env, never
  hardcoded).
- BASE_FROM: the single shared join graph every query reuses —
  fact_order_items foi JOIN dim_orders o (inner) + LEFT JOIN dim_products
  p, dim_brands b, dim_categories c, dim_stores s, dim_payment_methods pm,
  dim_customers cu. LEFT JOINs (not inner) so facts with null
  brand/category/payment FKs still count.
- Filters: frozen dataclass (hashable, so st.cache_data keys on it) with
  start_date, end_date (EXCLUSIVE upper bound), stores/categories/
  statuses tuples; previous_period() shifts the window back one full
  span for period-over-period deltas; split_in_half() halves the window
  (fallback baseline when the prior period is empty).
- _where(filters): shared WHERE + params — foi/o is_active true, order
  timestamp in [start, end), store/category/status IN-lists. Empty tuples
  are VALID: "no selection = match nothing" via expanding IN.
- _run(sql, params): marks tuple params as bindparam(expanding=True),
  executes on a short-lived connection, returns a DataFrame.
- get_filter_options() [ttl=3600]: distinct active stores, all
  categories, distinct active statuses, min/max order dates (sidebar
  bounds + preset anchors).
- get_gold_meta() [ttl=600]: active fact row count + max order timestamp
  (home header/footer).
- get_kpis(filters) [ttl=600]: revenue SUM(line_amount), DISTINCT orders,
  DISTINCT customers, aov = revenue/orders (0.0 guard when orders = 0).
- get_revenue_trend(filters, granularity) [ttl=600]: date_trunc buckets
  at day|week|month (whitelist-validated, ValueError otherwise).
- _DIMENSION_COLUMNS whitelist (store/category/brand/payment_method/
  order_status -> real "alias.column") + get_revenue_by(filters,
  dimension, limit) [ttl=600]: GROUP BY revenue DESC, NULL members
  excluded, LIMIT int-cast (never raw text).
- get_category_brand_treemap(filters) [ttl=600]: category x brand revenue
  matrix for the treemap.
- get_top_products(filters, limit=10) [ttl=600]: name/brand/category +
  revenue + units_sold, top-N by revenue.
- get_top_customers(filters, limit=10) [ttl=600]: name + revenue +
  DISTINCT orders, top-N.
- get_recent_order_lines(filters, limit=200) [ttl=600]: bounded newest-
  first sample (timestamp/store/customer/product/brand/category/qty/
  prices/status/payment) for the searchable table — deliberately NOT the
  full filtered set.

6. DEMO SEEDER — scripts/seed_demo_db.py (108 lines, NOT part of the pipeline)
--------------------------------------------------------------------------------
One-off utility that copies the gold schema from LOCAL Postgres into a
separate PUBLIC demo Postgres (e.g. free Neon/Supabase) so the hosted
demo never needs the real dev database reachable from the internet.
- Usage: `uv run python scripts/seed_demo_db.py "<target-postgres-URL>"
  [--schema gold]` (target DB must already exist; credentials stay on
  the command line, never hardcoded — the example URI in the docstring
  is deliberately commented for the security scanner).
- SOURCE_SCHEMA = POSTGRES_SCHEMA_GOLD from .env; TABLES (dims before
  facts for readability; no FKs are created on target): dim_brands,
  dim_categories, dim_payment_methods, dim_products, dim_stores,
  dim_customers, dim_orders, fact_order_items.
- Flow: CREATE SCHEMA IF NOT EXISTS on target -> per table
  `SELECT *` via pandas -> anonymize dim_customers -> to_sql(replace).
- anonymize_customers(df): deterministic PII scrub keyed off
  customer_id — "Customer <id>", "customer<id>@example.com", phone
  "555-0100", phone_extension NULL — so joins/aggregations behave
  identically with only identifying text changed.

7. CACHING & PERFORMANCE MODEL
--------------------------------------------------------------------------------
- st.cache_data(ttl=3600) on slow-changing filter options; ttl=600 on all
  data queries (KPIs, trends, breakdowns, meta). Refresh = clear cache +
  rerun (the documented `Refresh` pattern clears st.cache_data).
- Filters is frozen/hashable precisely so it can be a cache key; tuples
  (never lists) for the multiselect values.
- GROUP BYs run in Postgres; Streamlit receives tens/hundreds of rows,
  never the 30k-row fact table (except the deliberate 200-row sample).
- Expanding IN binds handle empty selections as "match nothing" instead
  of crashing or matching everything.

--------------------------------------------------------------------------------
8. RULES & GOTCHAS FOR ANYONE TOUCHING THE DASHBOARD
--------------------------------------------------------------------------------
1. Entry pages MUST bootstrap sys.path (copy the PROJECT_ROOT snippet
   from home.py) or `from dashboard...` / `from src...` imports fail.
2. NEVER run a page with bare `python` — always `streamlit run` (see §0).
3. NEVER pass indented/blank-line HTML to st.markdown — route every raw-
   HTML block through components._safe_html (the §3b lesson).
4. NEVER interpolate filter values into SQL — use bound params; new
   GROUP BY dimensions go through the _DIMENSION_COLUMNS whitelist.
5. New queries live in helpers/queries.py (+ re-export in lib/queries.py),
   new charts in lib/charts.py, new shared widgets in
   helpers/components.py — pages stay thin (import, filter, query, plot).
6. New tables need no dashboard code change as long as gold contracts +
   models cover them; sidebar options come from live DISTINCT queries.
7. Secrets: local runs use .env; Cloud uses st.secrets via lib/db.py;
   secrets.toml values never go into git, docs, logs, or screenshots.
8. home.py's "Full tabbed view lives in app.py" caption is STALE — there
   is no app.py; navigation is the sidebar multipage menu.
