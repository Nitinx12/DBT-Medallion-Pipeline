Two inconsistencies deserve honesty. First, some docs say \file{docker/Dockerfile} while the files are \file{Dockerfile.pipeline} and \file{Dockerfile.airflow}; the files win. Second, banners print \file{STEP n / 7} for eight stages because numbering starts at zero; the count is stages minus one, not an off-by-one in the runner. Third, GX asserts non-null FK ids while dbt relationships permit nulls (see Chapter~7); until product decides whether unknown lookups are legitimate, both stay as they are.

\section{Roadmap}

Near term: enable the Neon refresh cron, publish Data Docs, resolve the null-FK question, add bronze \file{schema.yml} depth. Medium term: dbt snapshots for customer and store history, BSON-date migration for native watermark pushdown, column masking for external gold access. Long term: change-stream CDC for near-real-time bronze.

\begin{keybox}
\item Limits are scoped and each maps to a concrete next step.
\item Inconsistencies are documented where users will trip over them.
\item Nothing on the roadmap requires re-architecture, only iteration.
\end{keybox}
